Give every agent a reviewable handoff

The latest agent releases are less about producing another answer and more about coordinating work across people, repositories, and tools. The engineering challenge: keep every handoff inspectable.

1. Chat-to-code is now a production entry point

On November 6, GitHub made @GitHub in Slack and Teams generally available. Teams can investigate bugs, create issues and open pull requests from conversations; generated issues and PRs now include conversation attribution. Try a narrowly scoped bug report from a team thread, but require the resulting PR to include the reproduction, affected repository, test evidence and reviewer.

Why this matters: Moving a request into chat should not erase its provenance or the acceptance criteria for shipping code.

2. Agent reviews need measurable outcomes

GitHub's November 5–6 changelog describes new Copilot code-review management controls and usage metrics, including a code-review feedback addressed rate. For your team, track three separate counts: findings raised, findings addressed, and regressions caught by tests. A review that produced comments is not necessarily a review that improved the code.

Why this matters: Measuring closed feedback loops beats measuring how many AI reviews ran.

3. Multi-agent work makes handoffs a security boundary

Independent reporting from The Verge describes Perplexity's new Teammates as ongoing agents with shared work context and multiple concurrent assignments. Perplexity's November 4 launch listing confirms the product. When one agent discovers a bug and another prepares a patch, require a written handoff: evidence, permissions, expected files, and explicit stop conditions.

Why this matters: A chain of plausible agent outputs can still lose scope, assumptions and accountability between steps.

4. Agent-generated fixes need a security receipt

A November 6 research preprint examines observable agent involvement in security-remediation commits linked to GitHub advisories; its reported 469 candidate advisories are observational, not a proof of patch quality. For every AI-assisted security change, save the advisory reference, diff, tests, scan results and human sign-off in the pull request.

Why this matters: Attribution tells you who helped; reproducible validation tells you whether the fix deserves trust.

Tool spotlight · launched November 4

Perplexity Teammates

What it does: Teammates are persistent agents that coordinate ongoing tasks using Perplexity Computer's projects, skills, memory and connected tools. Perplexity describes isolated environments and approval checkpoints; The Verge independently covered the release.

Why it was built: Long-running work often needs follow-up across multiple tasks, rather than a single prompt and answer.

Try it: If you have access, open Teammates on Perplexity's web app, create a teammate for a single low-risk repository, connect only the needed GitHub project, and ask it to investigate one recurring test failure. Require a short findings report and draft issue—not a direct merge. Compare its conclusions with CI logs before approving any follow-up.

Caveats: Perplexity says initial access is for Max subscribers on the web; availability and pricing may change. Connectors expose sensitive context, so limit repository access and require approval for writes. The tool's autonomous follow-through is a vendor claim, not an independent reliability guarantee. Official announcement listing · Independent coverage.

Why this matters: The most valuable persistent agent is one whose work can be paused, inspected, and safely handed to a human.

One thing to try before lunch

Add a five-line agent handoff receipt to your next AI-assisted PR: (1) original request and source, (2) files/tools allowed, (3) changes proposed, (4) tests and scan results, and (5) unresolved risks plus human approver. Ask a second agent to review the receipt against the actual diff; do not let it approve its own work.
