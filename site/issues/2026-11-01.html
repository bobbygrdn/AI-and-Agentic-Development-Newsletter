The harness is the product surface

The model is only one component of an agent. The useful engineering work is the harness around it: context, tools, state, permissions, feedback, and evidence. Build that layer deliberately and model choice becomes a replaceable implementation detail.

1. Define the execution contract before the prompt

Write down what the agent may read, which tools it may call, what counts as success, how long it may run, and what it must return for review. Treat this like an API contract: explicit inputs, bounded side effects, typed outputs, and a failure path. A prompt can explain intent; the contract makes the workflow operable.

Why this matters
Most agent failures are boundary failures—missing context, ambiguous authority, or an output that cannot be checked.

2. Give tools narrow names and narrow powers

Expose capabilities such as read_issue, run_tests, or prepare_patch instead of a single “do anything” shell. Return structured results with provenance and exit status. Keep write operations behind an explicit approval or safe-output step, and make the read-only path useful on its own.

Why this matters
Least-privilege tools reduce blast radius and make traces understandable to both humans and evaluators.

3. Evaluate the harness with the model held constant

Use the same model, task set, tools, and acceptance tests while changing one harness feature at a time: context retrieval, compaction, subagents, retries, or review. Track completion, tool errors, latency, tokens, correction time, and evidence quality. Recent research argues that tool use and task-specific subagents can matter more consistently than generic extra agents.

Why this matters
Without a controlled baseline, a “better agent” may simply be a better model, a luckier task mix, or a more generous evaluator.

4. Ship the handoff artifact, not just the answer

For every meaningful run, preserve the plan, files changed, commands executed, tests and checks, unresolved questions, and the next safe action. A durable handoff lets a maintainer resume or reject the work without replaying the entire conversation. It also creates the dataset you need to improve routing and instructions.

Why this matters
Reviewable evidence turns autonomy into a team capability instead of an opaque demo.
Tool spotlight · newly available in preview

Microsoft Copilot harness in Foundry Agent Service

What it does: Microsoft is making the multi-model harness developed for GitHub Copilot available through Microsoft Foundry. It supplies a managed execution loop for agents that reason, use tools, coordinate work, maintain context, and run in a managed environment. The same family of harness powers Copilot surfaces including the app, CLI, VS Code, and Copilot Studio.

Why it was built: Teams increasingly need to mix models without rebuilding the agent runtime around each one. Microsoft’s stated goal is to separate the execution system—context, tools, orchestration, and reliability—from the selected model, while keeping enterprise deployment and governance in the platform. Independent coverage highlights the practical tradeoff: the harness may improve consistency, but customers still need to measure model, compute, and lock-in costs for their own workload.

How to use it: In Foundry, start with a narrow workflow whose tools and success checks are already explicit. Define the instructions, skills, and evidence-producing tools; select a supported model; then run a small fixed benchmark. Compare the same tasks with your existing agent runtime, inspect traces and tool failures, and set a budget and approval boundary before expanding to writes or long-running jobs. Billing for the harness is scheduled to begin December 1, 2026, so include infrastructure and inference in the baseline.

One thing to try before lunch

Pick one repetitive repository task. Write a one-page execution contract, split its tools into read-only and write-capable groups, and define the evidence a reviewer needs. Run ten examples through your current agent and record success, tool errors, review time, and cost. Improve the harness before you swap the model.
