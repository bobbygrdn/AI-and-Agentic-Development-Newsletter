All Things AI Dev · Saturday recap

November 21, 2026 · Week of November 16–20

Measure the work, not the agent

Cheaper coding models, event-driven pull requests and a serious dependency compromise make the same point: a useful agent is a controlled engineering workflow, not just a capable model.

1. Model choice becomes a routing decision

On November 17, Microsoft introduced MAI Code 2 and Code 2 Flash at Ignite. Both are available in eligible GitHub Copilot experiences; Flash targets routine edits and explanations, while Code 2 targets more complex repository work. Microsoft reports favorable cost-performance results, but its price comparisons include promotional pricing and its benchmarks are not a guarantee for your codebase. Microsoft announcement · Ignite overview · Independent pricing context.

Try a cheap-first route for narrow changes, escalating only when tests fail or the scope expands. Compare accepted changes per dollar, including retries and reviewer time.

Why this matters: A model that costs less per token can still cost more per accepted fix.

2. Stop polling pull requests

GitHub introduced Event Streams in preview on November 17. Agents can subscribe to changes in reviews, commits, conflicts and checks without hosting a public webhook endpoint. This week's CLI update brings that interface into terminal workflows. GitHub announcement.

Use events as a signal to re-read the current pull request state, not as authorization to merge. Design for duplicate events, disconnects and stale commits. A bounded retry or manual fallback is still necessary.

Why this matters: Waiting for meaningful changes can conserve API calls and agent attention while keeping the workflow responsive.

3. The agent supply chain is part of the security boundary

On November 17, unauthorized versions 1.26.1 and 1.26.2 of Microsoft's Python agent-framework package were published and subsequently quarantined. Elastic's researchers found credential-stealing behavior that could execute when Python started, even without importing the framework. Independent reporting confirms the incident; the original access route and full impact remain uncertain. Elastic security research · SecurityWeek.

Inspect lockfiles, build records and cached images for the affected releases. If exposed, isolate and rebuild from verified clean artifacts, revoke and rotate credentials from a clean environment and review cloud and CI audit logs. Avoid starting Python in a suspect environment. Pin reviewed dependencies and restrict network and secret access even during builds.

Why this matters: An agent's sandbox cannot protect you if the dependency installation or build environment is already compromised.

4. Productivity is an outcome, not a usage metric

Business Insider reported this week that McKinsey and Cognition are working together to help enterprises demonstrate returns from coding agents. The reporting describes widely varying productivity outcomes among organizations, reinforcing that adopting a tool is not equivalent to improving delivery. Independent reporting.

Pick a baseline before a rollout: time to accepted change, regression rate, review minutes and total spend. Keep investigation work separate from delivery tasks so useful debugging is not incorrectly counted as waste.

Why this matters: Measure engineering outcomes rather than agent activity, generated lines or seat utilization.

Tool spotlight · GitHub CLI 2.105.0

What it does: Released November 18, this update adds preview gh event commands for listening to pull request events and managing subscriptions. Why it was built: GitHub wants scripts and agents to wait for changes instead of repeatedly querying unchanged state.

  1. Upgrade the CLI to 2.105.0 or later and check gh --version.
  2. Request Event Streams preview access using the GitHub announcement and authenticate with gh auth login if necessary.
  3. In a test repository, create a pull request and run the following command, substituting your URL.
gh event listen --resource https://github.com/OWNER/REPO/pull/NUMBER \
  --event com.github.pull_request.review.submitted.v1 --timeout 5m

Submit a review from an authorized account and inspect the returned JSON. Re-fetch the PR and confirm its head SHA before acting. Timeouts should leave the task waiting or escalate it, not authorize a merge. The preview requires approved access and its interface can change; the CLI upgrade alone does not grant access. Event Streams announcement · Versioned release notes mirror.

Why this matters: An event-driven agent can be idle between genuine work items instead of paying to check for them.

Weekend lab · One task, two routes, one receipt

  1. Choose a small repo bug and fix its acceptance tests before starting.
  2. Run your existing agent and a cheaper candidate in separate branches with identical permissions, time limits and tests.
  3. Record total spend, elapsed time, retries, review minutes and whether the change meets its acceptance criteria.
  4. Inspect dependency locks and test that the agent cannot access production secrets or merge without approval.
  5. Write a routing rule based on the observed results; repeat on several tasks before adopting it broadly.

Monday's starting point: keep the cheaper route for bounded work, use stronger models when evidence warrants escalation, and make every handoff independently verifiable.

Why this matters: A repeatable experiment turns weekly release news into a measurable improvement in your workflow.
