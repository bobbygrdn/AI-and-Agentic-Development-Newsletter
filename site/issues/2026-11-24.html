Make autonomy reviewable

The useful unit of agentic development is not the uninterrupted run. It is the smallest change a human can understand, test, and safely accept.

1. Claude Code is widening the host surface

Anthropic’s Claude Code 2.1.331, released November 23, adds Code Mode support in terminal sessions on Amazon Bedrock, Google Cloud’s Agent Platform, Microsoft Foundry, and Claude Platform on AWS. It also adds richer OpenTelemetry fields such as model, operation, and token usage, and fixes malformed local or WebSocket MCP replies that could leave calls hanging for up to 30 minutes.

The practical move is to treat host support and observability as part of the agent contract. Before enabling a new provider, capture the model identity, tool latency, token use, retries, and final outcome in the same trace. Add a timeout around every remote tool call and a resumable handoff when the timeout fires.

Why this matters: More places to run an agent increase portability, but only comparable traces make failures portable too.

2. OpenHands is making multi-agent work easier to inspect

OpenHands 1.45.0, released November 24, adds experimental Projects in Canvas, project conversations in the sidebar, files and pull requests beside chat, and nested sub-agent conversations under their parent. These are product changes, not proof that a workflow is correct—but they make the work graph more visible.

Use the same idea in your own harness: every sub-agent should have a parent task, a bounded responsibility, a named output artifact, and a visible status. Do not merge a child result just because the parent says it is complete; validate the artifact against the parent’s acceptance test.

Why this matters: A visible work graph makes delegation debuggable instead of turning parallelism into an opaque pile of transcripts.

3. The agent supply chain can execute before your code does

Wiz and the GitHub Advisory Database documented a compromise of Microsoft’s agent-framework PyPI package. Versions 1.26.1 and 1.26.2, published November 17, added a .pth startup hook that ran whenever Python started in the environment, even if the framework was never imported. The clean version was 1.26.0; the malicious releases were removed, but they may remain in caches and mirrors. Wiz analysis · GitHub Advisory.

Audit agent environments like production workloads: pin exact versions and hashes, prefer a reviewed internal mirror, scan wheels before execution, restrict outbound network access, and rotate credentials if an affected version touched a laptop or runner. “The package was removed” is not a remediation for an environment that already executed it.

Why this matters: Agent frameworks are part of your execution boundary; package installation is code execution, not harmless setup.

4. Review effort should follow risk, not habit

GitHub’s Copilot code-review settings now expose Lite, Balanced, Max, and Adaptive effort levels. Adaptive can choose effort based on pull-request complexity and risk, but it remains in public preview and never exceeds the maximum configured for the enterprise, organization, or repository. GitHub documentation.

Start with a policy, not a toggle. Route documentation and mechanical changes to a lighter review; route authentication, migrations, dependency updates, and cross-service changes to deeper review plus deterministic tests. Record the selected effort, findings, reviewer changes, and escaped defects so you can learn whether adaptive routing actually improves delivery.

Why this matters: Automatic effort selection is useful only when your repository has an explicit definition of “high risk.”

Tool spotlight · released November 23

Claude Code 2.1.331

What changed: Code Mode now works in more hosted terminal environments, the release adds an API connectivity section to claude doctor, improves tracing fields, supports optional plugin dependencies, and fixes several MCP and editing edge cases.

Try it:

  1. Upgrade one non-production development environment and record the exact version.
  2. Run a fixed task that exercises one repository, one MCP server, and one test command.
  3. Capture the trace fields, tool latency, token usage, retries, final diff, and test result.
  4. Repeat the same task on your current version or host, then compare accepted-change rate and reviewer effort—not just completion time.
  5. Keep the upgrade if the result is better without increasing unexplained permissions, cost, or review load.

Caveats: New host support does not make the host equivalent: model availability, identity, network policy, MCP authentication, data residency, and billing can differ. OpenTelemetry data can contain sensitive operational details, so review retention and access controls before exporting traces. The MCP hang fix reduces one failure mode; still enforce client-side timeouts and cancellation.

Why this matters: A tool upgrade is an engineering change; ship it with a baseline, an acceptance test, and a rollback path.

Today’s practical takeaways

  1. Give every delegated task a parent ID, owner, acceptance test, and reviewable output.
  2. Put a timeout and cancellation path around every remote tool call.
  3. Pin agent dependencies and inspect startup hooks, wheels, lockfiles, and caches before execution.
  4. Define high-risk change classes before enabling adaptive review effort.
  5. Baseline tool upgrades with accepted changes, reviewer time, failures, token cost, and rollback rate.

Pick one agent workflow today and produce a small receipt: what it changed, what it ran, what it was allowed to access, what failed, and what remains uncertain. That receipt is the boundary between useful autonomy and unreviewed activity.
