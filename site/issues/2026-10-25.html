Faster code, same bottleneck

AI can make implementation cheaper while leaving delivery expensive. The next agentic-development win is redesigning the handoffs around the code, not merely generating more of it.

1. Measure the whole delivery loop

Atlassian’s 2026 developer-experience report finds that 87% of surveyed developers say AI helps them write code faster, while 72% report the same or greater friction across the lifecycle. The practical response is to pair coding metrics with time-to-clarity, review wait time, merge conflict rate, release lead time, and escaped defects.

Why this matters
A faster implementation step does not improve delivery if work still waits for context, review, or release.

2. Give agents the missing context before asking for more code

Information discovery remains one of the biggest workflow frictions. Before delegating implementation, ask an agent to build a context packet: relevant owners, constraints, existing patterns, acceptance tests, and open decisions. Have the developer approve that packet before the agent edits files.

Why this matters
Good context prevents fast agents from converting ambiguity into rework.

3. Automate the handoffs, not just the typing

Use agents to turn a reviewed change into the next useful artifact: a test plan, migration checklist, release note, review summary, or incident runbook. Keep each handoff structured and independently verifiable. The agent should expose what it inferred and what it could not determine, rather than silently filling gaps.

Why this matters
Workflow automation compounds when it removes waiting and coordination overhead instead of producing a larger queue of code to inspect.

4. Make review capacity a first-class budget

AI-generated output still consumes human attention. Set a change-size threshold, require tests and evidence before review, and route low-risk mechanical work separately from architectural changes. If the review queue grows, reduce agent concurrency or narrow the task boundary before increasing generation capacity.

Why this matters
The bottleneck moves to the scarce resource—experienced judgment—unless your system actively protects it.
Tool spotlight · newly released environment

ServiceNow ToolSmith

What it does: ToolSmith is an agentic developer environment for building the automations that ServiceNow EmployeeWorks assistants use. Developers describe the desired outcome in natural language; ToolSmith plans the work, implements integrations, and produces tools intended to be token-efficient and reliable across ServiceNow’s API surface.

Why it was built: ServiceNow says the goal is to reduce the gap between an employee’s workflow need and a governed assistant capability. Instead of hand-building every integration from scratch, developers can use a domain-aware environment trained on more than 75,000 APIs and keep the work inside an enterprise platform with administrator controls.

How to use it: Start from one narrow employee workflow and specify the trigger, systems touched, data returned, failure behavior, and approval point. Let ToolSmith draft the plan, inspect the generated integration, and test it against representative cases before publishing it to an assistant. Treat its natural-language speed as a way to explore and validate workflows—not as a reason to skip API permissions, negative tests, or human review.

One thing to try before lunch

Choose one agent-assisted task that regularly stalls after coding. Instrument three timestamps: context packet approved, change ready for review, and change released. For the next five tasks, ask the agent to produce the handoff artifact automatically, then compare delivery time and rework—not lines changed.
