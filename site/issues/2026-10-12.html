More code, longer queues: learning to work with agents

Today’s evidence points to a practical truth: AI agents can speed up coding, but the value still depends on how teams scope, test, review, and ship their work.

AI development & agentic practice   ·   5–7 minute read

Today’s agent story is bigger than a model launch. New evidence suggests coding agents can help teams produce more code, while review and delivery remain the places where work can pile up. The skill to practice is not simply asking an agent to do more; it is designing the handoff so that its work is small enough to verify and useful enough to ship.

The work behind the work

More code is not automatically more software

A new working paper from researchers at Harvard and the University of Pennsylvania analyzes engineering activity across roughly 700 firms. After organizations adopted coding agents, the researchers estimate increases in lines of code, commits, and pull requests. But they did not find a statistically significant increase in resolved Jira issues or epics. They also observed longer review times and more requested changes. The paper uses firm level adoption data and a difference in differences design; those results describe this dataset and period, not a guarantee about every team or tool. Read the paper.

That gap offers a practical lesson: aim an agent at a well-bounded piece of work, and make the acceptance evidence part of the request. Ask for a focused diff, the tests that demonstrate the behavior, and any assumptions it could not verify. Track work that reaches “done” in production, not just output volume.

Why this mattersIf review and delivery are the bottlenecks, generating more code faster can simply move the queue downstream.
A useful counterpoint

Recent research finds testing discipline can improve

A paper published October 5 in the proceedings of the International Symposium on Empirical Software Engineering and Measurement followed 669 developers across 103 repositories and compared them with 228 controls. It reports longer pull request descriptions and smaller improvements across three testing measures after agent adoption, while coding effort stayed stable. Review became faster, less detailed, and more permissive in both agent and control repositories, so the authors attribute that pattern to broader changes rather than agents alone. Read the open access study.

Put the two studies together carefully: agents may increase coding throughput and teams may respond with better descriptions and testing, yet organizational output still depends on review, deployment, and the actual value of the change. A useful habit is to ask the agent to explain what each test proves, then inspect both the test and implementation. This makes “tests passed” more informative than a bare status line.

Why this mattersAgentic development gets better when testing and review are designed into the task instead of added after generation.
“Ask for the smallest change that proves the behavior, then make the proof easy to inspect.”A practical handoff for today
New tool spotlight · October 12

Muse Wonder brings long-running agents into Meta’s coding lineup

What it does

Meta announced Muse Wonder and Muse Wonder Full today. Meta describes them as models for coding, computer use, and longer running agent tasks that can plan, delegate to subagents, call tools, and recover from errors. The product page says Muse Code brings multi-agent coding into a terminal workflow. These capability descriptions and benchmark claims come from Meta; independent reporting confirms the launch but does not yet establish comparative real world performance. Meta’s launch announcement · TechCrunch’s independent report.

Why it was built

Meta says it designed the family for work that unfolds over time: Active Memory carries relevant context across conversations, while Active Focus keeps trying alternatives, recovers from errors, and checks in before important actions. In other words, the product is aimed at tasks that require continuity and follow through, not just one answer in a chat. Those are the company’s intended capabilities; they should be validated on your own tasks.

How to try it

For terminal based coding, start with Muse Code and give it a small, reversible repository task: for example, add a missing test or document one module. State the target behavior, files or boundaries to preserve, and the checks to run. Review its plan and diff before accepting changes. Developers can also call Muse Wonder through Meta’s Model API or connect it to supported tools; Meta provides an OpenAI SDK compatible quick start. Muse Wonder Full is offered through eligible Muse Code subscriptions, while Wonder is available through the API and Muse Code. See current access and developer details.

Why this mattersLong running agents shift the work from composing a perfect prompt to setting durable goals, permissions, checkpoints, and a clear definition of “finished.”
Practice for your next session

Use a three part agent handoff

1. Outcome: describe the user visible behavior, not just the files to edit. 2. Guardrails: name what must stay unchanged, and ask the agent to stop before destructive or external actions. 3. Evidence: request the exact checks, a short diff summary, and any uncertainty. For a multi step task, have it propose a plan first; approve or narrow the plan before it fans out. Afterward, use a clean review pass focused on edge cases and the tests themselves.

Why this mattersA repeatable handoff makes agent output easier to compare, review, and improve from one task to the next.
