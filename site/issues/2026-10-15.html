Scale the workflow, contain the blast radius

Claude can now write programs that orchestrate large fleets of agents. That is an impressive step up in leverage—and a reminder that budgets, permissions, provenance, and failure handling are part of the product, not cleanup work.

What matters this morning

1. Multi-agent orchestration becomes programmable

Anthropic’s Claude Managed Agents now supports dynamic workflows in beta. A lead agent can write a workflow program, split work into phases, run agents in parallel, pass results between them, repeat steps, and handle failures while the server executes the run in the background. Anthropic documents ceilings of up to 1,000 agents over a run’s lifetime and 64 working threads at once, though limits may change.

Why this matters
Parallelism is valuable when tasks are truly independent. Before fanning out, define the merge strategy, evidence format, retry limit, and the condition that stops further work.

2. Agent safety is becoming an accountability question

Reuters reported on October 15 that the U.S. FTC sent civil subpoenas to OpenAI and Anthropic seeking information about safety incidents, safeguards, marketing, and privacy practices. Separately, ByteDance’s Seed unit announced an Alignment & Preparedness team focused on safety training, automated vulnerability testing, behavior monitoring, agent test environments, and independent evaluation.

Why this matters
Teams shipping agents should assume they may eventually need to explain what an agent could access, what it actually did, which guardrails fired, and who approved consequential actions.

Reuters on the FTC inquiry · Reuters on ByteDance’s safety team

3. Design for prompt injection to sometimes succeed

A 2026 paper argues that contextual manipulation can defeat defenses based only on separating data from instructions. The practical conclusion is not to abandon detection; it is to make successful manipulation less consequential. Give agents narrow tools, isolate sensitive data, require approval for irreversible actions, and validate outputs outside the model’s own reasoning loop.

Why this matters
A perfect detector is not a dependable security boundary. Limit the agent’s authority so one malicious document, webpage, or tool response cannot become a system-wide incident.

“AI Agents May Always Fall for Prompt Injections” · OpenAI’s defense-in-depth approach

4. Make agent-written CI reproducible

GitHub released Actions workflow dependency lockfiles in public preview on October 14. A lockfile records exact commits for actions, transitive dependencies, and reusable workflows, so reviewed code remains the code that runs even if a tag or branch later moves. GitHub cautions that locking does not prove a dependency is safe; it preserves the reviewed version.

Why this matters
When agents create or edit CI workflows, a readable lockfile gives reviewers a stable dependency diff and reduces the chance that a moving tag changes behavior after approval.

Tool spotlight: Claude Managed Agents dynamic workflows

What it does. Dynamic workflows let a Claude Managed Agent write and launch a program that coordinates many agent threads. The program can fan work out, sequence phases, share files in the session sandbox, aggregate results, retry failed work, and continue in the background.

Why it was built. A single conversational loop is a poor fit for work containing hundreds of similar inputs or several distinct phases. Anthropic uses document review as an example: independent readers can process batches, a synthesis phase can reconcile findings, and a final phase can produce one result.

How to use it safely.

  1. Enable workflows explicitly in the agent’s multiagent configuration and start with a low session budget.
  2. Describe when a workflow is appropriate—and when ordinary single-agent work is preferred—in the system prompt.
  3. Require every worker to return the same small schema: finding, evidence, confidence, and unresolved question.
  4. Give worker agents read-only tools by default; reserve writes and external actions for a final, separately approved phase.
  5. Set maximum rounds and a failure policy. Do not let “try again” become an unbounded token loop.
  6. Observe the event stream and sample worker threads before trusting the aggregate.

A good first experiment is repository reconnaissance: assign separate read-only agents to architecture, tests, dependencies, security-sensitive surfaces, and recent churn, then have one synthesis agent produce a cited map. Keep implementation out of the first run so you can evaluate orchestration quality without risking edits.

One thing to try before lunch

Write a four-line “fan-out contract” for your next multi-agent task: maximum workers, maximum rounds, evidence format, and stop condition. If you cannot state all four, the task is not ready to scale.
