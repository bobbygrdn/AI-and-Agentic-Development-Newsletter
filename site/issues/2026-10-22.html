Choose the workflow before the agent

Anthropic’s Claude Duet is the latest sign that always-on agents are moving into everyday work. The useful counter-move for developers is selection: start with the workflow, define the value, then choose the smallest agent architecture that can prove it.

What matters this morning

1. “Agentic” is a workflow property, not a product label

Claude Duet is designed to run in the background, brief users on connected apps, surface tasks, and ask for approval when needed. That is a meaningful product direction—but it does not make every task a good agent candidate. If a process is deterministic, a normal workflow or RPA may be cheaper, easier to test, and easier to explain. Reserve agents for work that genuinely needs context, coordination, or judgment inside explicit boundaries.

Why this matters: The best agent is often the one you can replace with a simpler system after mapping the workflow.

2. Measure the old process before you automate the new one

Recent practitioner guidance emphasizes a clear baseline: time per case, error rate, escalation rate, queue age, and human minutes. Record the current distribution, not just an average. Then define what “better” means before writing prompts or wiring tools. A prototype that saves model tokens but increases exception handling is not an improvement.

Why this matters: Without a baseline, an agent demo can create motion without creating value.

3. Give the agent a budget and a stopping rule

Long-running agents need explicit limits for time, tool calls, parallel workers, and spend. Make the agent return a useful partial result when it reaches a limit, with the unresolved work and evidence attached. For repeated workflows, log the budget consumed by each stage so you can see whether failures come from the model, the tools, or an over-ambitious plan.

Why this matters: Bounded failure is a product feature; unbounded persistence is an operating expense.

4. Separate exploration from commitment

Let agents search, summarize, compare, and draft in parallel—but route writes, purchases, messages, deployments, and other durable effects through a narrow commit step. This gives you the speed benefit of multiple workers without making every exploratory branch an independent source of side effects. Review the final structured proposal, not a pile of hidden subagent transcripts.

Why this matters: Parallel reasoning should expand options, not multiply irreversible actions.

Tool spotlight · Public beta

OpenAI Agents API

What it does. The Agents API is a managed cloud-agent service built around the Codex harness. It lets developers specify a task, model, tools, and environment; use hosted or partner sandboxes; maintain long sessions; search for tools on demand; and delegate bounded work to subagents.

Why it was built. Teams were rebuilding the same orchestration layer: context compaction, tool routing, parallel execution, durable sessions, and sandbox management. The API packages those mechanics so developers can focus on their domain tools, knowledge, and user experience.

How to use it.

  1. Start with the Agents API overview and choose a small workflow with a measurable baseline.
  2. Define the agent’s environment and tools narrowly. Load tool definitions on demand rather than exposing an entire catalog on every turn.
  3. Set a session budget: maximum duration, tool-call count, spend, and concurrent subagents. Return a partial artifact when the budget is exhausted.
  4. Run the same evaluation set against the old process and the agent. Compare completion quality, latency, cost, and human correction time before widening access.

Why this matters: A managed harness can remove plumbing, but it does not remove the developer’s job of choosing the right workflow and proving the result.

One thing to try before lunch

Take one task you are tempted to agentify. Write two alternatives: a deterministic workflow and a bounded agent. For each, list the inputs, tools, human approvals, success metric, maximum cost, and failure handoff. If the deterministic version wins on the baseline, keep it—and save your agent budget for a harder problem.

Why this matters: Comparing architectures is faster than discovering after launch that the “agent” was expensive glue code.
